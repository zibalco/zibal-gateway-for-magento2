# ماژول درگاه پرداخت زیبال برای مجنتو ۲

این ماژول درگاه پرداخت [زیبال](https://zibal.ir) را به‌عنوان یک روش پرداخت به صفحهٔ تسویه‌حساب (checkout) مجنتو ۲ اضافه می‌کند.

## پیش‌نیازها

- مجنتو ۲.۴ یا بالاتر
- دسترسی SSH به سرور
- کد مرچنت فعال زیبال
- واحد پول پایهٔ فروشگاه (Base Currency) باید **ریال ایران (IRR)** باشد

## نصب

### ۱. انتقال فایل‌ها

محتویات ماژول را در پوشهٔ اصلی مجنتو طوری قرار دهید که ساختار پوشه‌ها دقیقاً به این شکل باشد:

```
app/code/ChalakSoft/Zibal
```

نام پوشه‌ها به حروف بزرگ و کوچک حساس است.

### ۲. فعال‌سازی ماژول

با SSH وارد سرور شوید، به پوشهٔ اصلی مجنتو بروید و این دستورها را به ترتیب اجرا کنید:

```bash
php bin/magento module:enable ChalakSoft_Zibal
php bin/magento setup:upgrade
php bin/magento setup:di:compile
php bin/magento setup:static-content:deploy -f fa_IR en_US
php bin/magento cache:flush
```

## تنظیمات

در پنل مدیریت به این مسیر بروید:

**Stores ← Configuration ← Sales ← Payment Methods ← Zibal**

| تنظیم | توضیح |
|---|---|
| Enabled | فعال یا غیرفعال کردن درگاه. پس از نصب، درگاه به‌صورت پیش‌فرض **غیرفعال** است. |
| merchantID | کد مرچنت زیبال. تا این فیلد پر نشود، درگاه در checkout نمایش داده نمی‌شود. |
| نرخ سایت تومان است؟ | اگر قیمت‌های فروشگاه به **تومان** وارد شده‌اند، «Yes» را انتخاب کنید تا مبلغ پیش از ارسال به زیبال به ریال تبدیل شود (×۱۰). |
| عنوان | عنوانی که مشتری در صفحهٔ پرداخت می‌بیند. |
| وضعیت سفارش قبل از ارسال به بانک | وضعیت سفارش پیش از پرداخت. |

پس از ذخیرهٔ تنظیمات، کش را پاک کنید:

```bash
php bin/magento cache:flush
```

## آزمایش درگاه

برای آزمایش بدون پرداخت واقعی، مقدار `zibal` را در فیلد merchantID وارد کنید. این مرچنت تستی زیبال است و همهٔ پرداخت‌ها را بدون کسر پول تأیید می‌کند.

> **هشدار:** پیش از راه‌اندازی فروشگاه حتماً مرچنت واقعی خود را جایگزین `zibal` کنید. در غیر این صورت سفارش‌ها بدون دریافت پول، «پرداخت‌شده» ثبت می‌شوند.

## روند پرداخت

1. مشتری سفارش را ثبت می‌کند و به درگاه زیبال منتقل می‌شود.
2. پس از پرداخت، زیبال مشتری را به فروشگاه برمی‌گرداند.
3. ماژول پرداخت را از سرور زیبال استعلام می‌کند و شمارهٔ سفارش و مبلغ را با سفارش تطبیق می‌دهد.
4. در صورت موفقیت، برای سفارش فاکتور (Invoice) صادر می‌شود، وضعیت آن به «Processing» تغییر می‌کند و ایمیل تأیید سفارش و فاکتور برای مشتری ارسال می‌شود. ایمیل تأیید سفارش تا پیش از پرداخت موفق ارسال نمی‌شود.
5. اگر پرداخت انجام نشده باشد، سفارش لغو می‌شود.

پس از پرداخت موفق، کد پیگیری (trackId)، تاریخ و ساعت پرداخت و شماره کارت ماسک‌شدهٔ پرداخت‌کننده در بخش اطلاعات پرداخت سفارش نمایش داده می‌شود. شماره کارت در ایمیل و PDF سفارش نمی‌آید.

اگر انتقال به درگاه ناموفق باشد (مثلاً قطعی ارتباط با زیبال)، سفارش لغو و سبد خرید مشتری بازگردانده می‌شود تا بتواند دوباره تلاش کند.

اگر مشتری برای سفارشی که قبلاً لغو شده پرداخت کند، آن تراکنش تأیید (verify) نمی‌شود تا مبلغ به‌صورت خودکار به مشتری بازگردد و موضوع در تاریخچهٔ سفارش ثبت می‌شود.

اگر پرداخت انجام شده باشد ولی مبلغ یا شمارهٔ سفارش مغایرت داشته باشد، سفارش در وضعیت **On Hold** قرار می‌گیرد و جزئیات در تاریخچهٔ سفارش ثبت می‌شود تا مدیر آن را بررسی کند. اگر ارتباط با زیبال قطع شود، سفارش لغو نمی‌شود و همراه با کد پیگیری (trackId) برای بررسی دستی باقی می‌ماند.

## امنیت آدرس بازگشت (Callback)

آدرس بازگشت از درگاه فقط یک توکن رمزنگاری‌شده دارد، مثلاً:

```
https://shop.example/zibal/index/callback/t/0.Q3k9xV2mL8.../
```

- شمارهٔ سفارش، store و زمان ثبت سفارش داخل توکن رمزنگاری می‌شوند (با کلید `crypt/key` در `app/etc/env.php`) و از بیرون خواندنی یا قابل تغییر نیستند.
- هر توکن مخصوص یک تراکنش است و **فقط یک بار** قابل استفاده است. باز کردن دوبارهٔ لینک (مثلاً از تاریخچهٔ مرورگر) رد می‌شود.
- شمارهٔ سفارش به‌عنوان `orderId` به زیبال ارسال نمی‌شود و فقط در «توضیحات» تراکنش در پنل زیبال دیده می‌شود.

> **هنگام به‌روزرسانی از نسخه‌های قبلی:** پرداخت‌هایی که پیش از نصب این نسخه به درگاه رفته‌اند توکن ندارند و بازگشتشان رد می‌شود. به‌روزرسانی را زمانی انجام دهید که مشتری در حال پرداخت نباشد، یا پس از آن، پرداخت‌های همان چند دقیقه را از پنل زیبال بررسی کنید.

پس از نصب، یک بار با مرچنت تستی `zibal` پرداخت کامل انجام دهید تا مطمئن شوید بازگشت از درگاه درست کار می‌کند.

## گزارش‌ها (Log)

خطاها و رویدادهای مهم درگاه در این فایل ثبت می‌شوند:

```
var/log/zibal.log
```
